# Meeting Transcriber v0.2

로컬 회의 음성 전사 + 화자분리 + 기존 TXT 재편집 초안입니다.

## v0.2 변경점

1번 탭의 입력 방식이 2개로 분리되었습니다.

### 1) 음성 해석하기
- 기존 기능 유지
- faster-whisper 로컬 STT
- pyannote 로컬 화자분리
- 감지된 화자에 사용자가 직접 이름 지정
- Transcript 발언 직접 수정
- TXT 저장

### 2) 기존 TXT 불러오기
TXT 내용을 보고 자동으로 두 방식 중 하나로 처리합니다.

#### 구조화 TXT
이 프로그램이 저장하는 아래 형식을 인식합니다.

```text
[00:03] 김대리
이번 설치 일정에 대해서 말씀드리겠습니다.

[00:11] 박과장
그러면 10월 둘째 주로 잡으면 될까요?
```

- 시간 복원
- 화자 복원
- 발언 복원
- 복원된 화자 이름을 다시 수정 가능
- 수정 후 같은 구조를 유지해 TXT 저장 가능

#### 일반 TXT
시간/화자 헤더가 없는 일반 메모라면:

```text
설치 일정은 10월 둘째 주로 논의
현장 일정 재확인 필요
금요일까지 자료 전달
```

- 각 비어 있지 않은 줄을 편집 가능한 발언 행으로 표시
- 시간/화자 정보는 억지로 생성하지 않음
- 저장 시에도 일반 TXT 형식을 유지

## 코드 구조

- `main.py`
  - PyQt6 UI
  - 음성/TXT 입력 선택
  - 화자 이름 매핑
  - Transcript 표시/수정/저장
- `stt_engine.py`
  - STT 전용
  - 향후 잡음 제거, 포맷별 전처리, 모델 변경을 이곳에서 확장
- `speaker_diarizer.py`
  - 화자분리 전용
  - diarization과 STT 타임스탬프 결합
- `text_importer.py`
  - TXT 형식 판별
  - 구조화 TXT의 시간/화자/발언 복원
  - 일반 TXT fallback

## 기본 STT 설정
- model: `small`
- device: `cpu`
- compute type: `int8`
- language: `ko`

초기 호환성을 위해 CPU 기준으로 잡았습니다.

## 모델 다운로드와 보안
음성 추론은 로컬에서 수행하도록 설계했습니다. 단 모델이 PC에 없으면 최초 모델 다운로드에는 인터넷 연결이 사용될 수 있습니다.

TXT 불러오기/수정은 로컬 파일 처리만 수행합니다.

pyannote `speaker-diarization-community-1`은 최초 접근 시 Hugging Face 사용 조건 동의 및 token이 필요할 수 있습니다. HF token은 UI 입력 또는 환경변수 `HF_TOKEN`으로 전달하며 현재 초안에서는 저장하지 않습니다.

## v0.4 추가 기능

### 음성 언어
- 한국어 (기본)
- 자동 감지
- 영어
- 중국어
- 일본어

`transcribe` 모드이므로 선택 언어로 번역하는 기능이 아니라,
음성의 주 언어를 STT에 알려주는 설정입니다.

### STT 품질
- 빠름 → `small`
- 균형 → `medium`
- 정확 → `large-v3`

현재 CPU 호환성을 우선해 `device=cpu`, `compute_type=int8`은 유지합니다.
큰 모델은 다운로드 용량, RAM 사용량, 처리 시간이 크게 증가할 수 있습니다.

### 모델 미리 불러오기
분석 전에 다음 버튼으로 모델을 메모리에 준비할 수 있습니다.

- `STT 모델 불러오기`
- `화자 모델 불러오기`

미리 불러오지 않아도 `분석 시작` 시 기존처럼 자동 로딩됩니다.
한 번 로딩된 모델은 같은 프로그램 실행 세션에서 재사용됩니다.

STT 품질을 변경하면 기존에 로딩된 STT 모델은 해제된 것으로 처리하고,
새 품질의 모델을 다시 불러와야 합니다.


## v0.5 추가 기능 - 성능 설정

STT 설정과 별도로 `성능 설정` 영역을 추가했습니다.

### GPU 자동 사용
기본값:

```text
☑ GPU 사용 가능하면 자동으로 사용
```

- NVIDIA GPU가 Windows에서 감지되면 STT는 `cuda + float16`을 우선 사용합니다.
- GPU를 감지하지 못하거나 체크를 끄면 `cpu + int8`을 사용합니다.
- 실제 CUDA/CTranslate2 환경 문제로 STT GPU 모델 로딩이 실패하면 CPU 모드로 자동 fallback 합니다.
- pyannote 화자분리도 GPU 사용을 시도하고, GPU 전환이 불가능하면 CPU로 유지합니다.

### 처리 장치 상태
UI에 현재 판단된 처리 장치를 표시합니다.

예:

```text
처리 장치: NVIDIA GeForce RTX 3060 · GPU 사용
```

또는:

```text
처리 장치: CPU · NVIDIA GPU 감지 안 됨
```

GPU 자동 사용 설정을 바꾸면 이미 메모리에 올려둔 STT/화자 모델은
처리 장치가 달라질 수 있으므로 다시 불러오도록 초기화합니다.

> `nvidia-smi`로 GPU가 보인다는 것은 NVIDIA GPU와 드라이버가 감지된다는 의미입니다.
> 실제 faster-whisper GPU 실행에는 CTranslate2가 요구하는 CUDA/cuDNN 런타임도 정상이어야 합니다.


## v0.6 - STT / 화자 라벨링 완전 분리

- 음성 파일과 텍스트 파일을 독립 입력으로 관리합니다.
- `STT 실행`은 음성 -> 타임라인 텍스트 생성만 수행합니다.
- `현재 텍스트에 화자 라벨링`은 이미 존재하는 타임라인 텍스트 + 선택된 음성 파일만 사용합니다.
- 따라서 `STT -> 화자 라벨링`도 가능하고, `기존 타임라인 TXT -> 화자 라벨링`도 가능합니다.
- 일반 TXT처럼 시간 정보가 없는 텍스트는 음성과 대응시킬 기준이 없으므로 화자 라벨링을 막습니다.
- 화자 라벨링 전에 텍스트의 최대 타임라인이 선택된 음성 길이를 초과하는지 검증합니다. 1초 이내의 컨테이너 반올림 차이만 허용합니다.
- 구조화 TXT의 마지막 발언처럼 종료 시간이 없는 경우 선택된 음성 길이를 마지막 종료 시간으로 사용합니다.
- 화자 모델 단계에서 오류가 발생해도 이미 만들어진 STT/불러온 텍스트는 지우지 않습니다.
- 음성 길이 확인은 WAV 표준 라이브러리 또는 faster-whisper 스택의 PyAV를 사용하므로 시스템 FFmpeg PATH 설치를 요구하지 않습니다.


## v0.7 - STT / 화자 모델 GPU 옵션 분리

- STT의 `STT GPU 자동`과 화자분리의 `화자 GPU 자동`을 별도로 선택합니다.
- STT는 faster-whisper/CTranslate2 CUDA 경로를 사용합니다.
- 화자분리 모델은 Hugging Face에서 받은 pyannote pipeline을 PyTorch CUDA로 이동해 사용합니다.
  (HF Token/다운로드 자체가 GPU를 쓰는 것이 아니라, 다운로드된 모델의 추론이 GPU를 사용합니다.)
- 한쪽 GPU 옵션을 바꿔도 다른 쪽 모델 캐시는 유지합니다.
- 화자분리용 FFmpeg shared DLL은 기본적으로 `C:\Tools\ffmpeg\bin`을 화자 모델 로딩 직전에만 현재 Python 프로세스에 등록합니다.
  다른 위치를 쓰려면 환경변수 `MOMCREATOR_FFMPEG_BIN`으로 지정할 수 있습니다.


## v0.7.1 - STT → 화자 라벨링 연속 실행 옵션

- `연속 실행 (STT → 화자 라벨링)` 체크박스를 추가했습니다.
- 체크 해제(기본값): v0.7과 동일하게 `STT 실행`과 `현재 텍스트에 화자 라벨링`을 각각 독립 실행합니다.
- 체크: 음성 파일을 선택한 뒤 STT 버튼 한 번으로 `STT → 화자 라벨링`을 순차 실행합니다.
- 실제로 두 모델을 동시에 병렬 실행하는 방식이 아니라, STT가 성공한 뒤 그 타임라인 텍스트를 그대로 화자 라벨링 단계에 넘기는 안전한 연속 실행입니다.
- STT가 실패하거나 사용자가 중지하면 화자 라벨링은 자동 시작되지 않습니다.
- STT 완료 결과는 화자 라벨링 실패 여부와 관계없이 그대로 유지됩니다.
- 기존의 `타임라인 TXT + 음성 → 화자 라벨링` 독립 실행 기능도 그대로 유지됩니다.

## v0.7.2 - 작업 경과 시간 / 총 소요시간 표시

- STT 또는 화자 라벨링을 시작하면 진행률 옆에 실제 벽시계 기준 `경과 00:00`이 1초 단위로 표시됩니다.
- STT는 기존 오디오 처리 위치(`현재 시간 / 전체 음성 길이`)와 함께 실제 처리 경과시간을 동시에 볼 수 있습니다.
- 단독 실행 완료 시 `총 소요 00:00`을 표시합니다.
- 연속 실행(STT → 화자 라벨링)에서는 작업 전체 시작 시각을 유지합니다.
  - STT 완료 시 STT 단계 소요시간 표시
  - 화자 라벨링 진행 중 전체 경과시간 표시
  - 최종 완료 시 `STT 소요 / 화자 소요 / 총 소요`를 함께 표시
- 중지 또는 오류가 발생한 경우에도 중지/실패 시점까지의 경과시간을 남깁니다.
